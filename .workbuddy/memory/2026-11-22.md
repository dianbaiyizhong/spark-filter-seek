# 2026-11-22

## 从零搭建 spark-filter-seek Maven 工程

- 目标：Spark SQL DataSource V2，ORC/Parquet 两阶段读取。阶段一只读过滤列并返回 file + stripe/rowGroup + rowid，阶段二按位置只读取 SELECT 所需列。Druid 解析 SQL WHERE。
- 技术选型：Java 实现；Spark 3.5.1 / Scala 2.12 / Hadoop 3.3.4 / ORC 1.9.2 / Parquet 1.13.1 / Druid 1.2.23；Spark、Hadoop、ORC、Parquet 均为 provided，Druid 打进 with-dependencies jar。
- 关键实现：
  - `DruidSqlParser` + `SparkFilterConverter` 统一产出 `SeekPredicate` 谓词树；不支持的 Spark Filter 保留给 Spark 重算。
  - ORC 阶段一用 `RecordReader.include(boolean[])` 只读过滤列，`getStripeStatistics()` 做 min/max 剪枝，`seekToRow()` + 向量化 batch 扫描；阶段二 `seekToRow(globalRowId)` 定位。
  - Parquet 阶段一用 `readRowGroup` + `ColumnReaderImpl` 读过滤列页；字典编码必须用自定义 `PrimitiveConverter`（直接 `getBinary()` 会抛 UnsupportedOperationException）；阶段二只打开命中 row group。
  - 位置模型 `SeekHit(file, blockIndex, rowInBlock, globalRowId)`；`SeekPlan` 汇总命中与剪枝计数。
- 验证：`mvn package`（JDK 17）通过；端到端 demo 三条链路全部命中预期（ORC 64、Parquet LIKE 95、Druid seek.sql 108）。
- 环境注意：本机默认 JDK 25 会让 Hadoop UGI 报 `Subject.getSubject is not supported`，测试需指定 JDK 17；直接 java 运行还需加 `--add-opens`（surefire 已配置）。
- 已知限制：仅顶层基本类型；Parquet INT96 时间戳不支持；无谓词退化为列裁剪全扫；阶段二 Parquet 未做行级 skip。详见 README。

- 按用户要求把根包名从 `com.example.spark.seek` 改为 `com.saprk.spark.filterseek`（`saprk` 为用户原文拼写，已照用），源码目录同步迁移。

## JDK 8 兼容

- `pom.xml` 基础属性改为 `maven.compiler.source/target=1.8`，移除硬编码 `release 11`；新增 `jdk9plus` profile（activation jdk `[9,)`），JDK 9+ 自动用 `maven.compiler.release=8`，并把 `--add-opens` 只放在该 profile 的 surefire 配置里，JDK 8 下不会传这些参数。
- XML 注释里不能出现连续 `--`（如 `--release`），否则 POM 解析失败。
- 验证：本机 Corretto 8（1.8.0_412）`mvn clean package` 全绿（5 tests，命中 64/95/108）；JBR 17 同样全绿，`javap` 确认项目类与 Druid 类 major version 均为 52。
- README 已更新为 JDK 8 构建说明；Spark 3.5.1 / Scala 2.12 本身兼容 Java 8。
