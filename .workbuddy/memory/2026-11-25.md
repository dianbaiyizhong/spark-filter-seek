## 大小写可配置 + lower() 解包 + IN/LIKE 预编译

- 用户反馈：`lower(name) = '11'` 下推不生效，且担心大 IN 列表每行线性判断过慢。
- 谓词模型：`Comparison`/`In`/`Like` 增加 `Boolean ignoreCase` 覆盖字段（null 表示用全局配置）；新增 `PredicateCase` 统一大小写语义与 canonical key 规范化。
- Druid 解析：`columnRef()` 会解包 `lower/lcase/upper/ucase`（可嵌套），并给该叶子强制 `ignoreCase=TRUE`，因此即使全局关闭大小写无关仍保持 SQL 语义；其他函数显式报错，不静默忽略。
- 配置：`spark.filterseek.ignoreCase`（SparkConf，默认 true）与单次读取覆盖 `seek.ignoreCase`；driver 在 `SeekScan.planInputPartitions` 解析后写入分区 confMap，executor 不依赖 SparkSession。实现见 `ConfUtils.ignoreCase`。
- 求值优化：`PredicateEvaluator` 改为 compile-once 实例，IN 预构建 HashSet（按字符串/数值域分别规范化），LIKE 预编译 Pattern（CASE_INSENSITIVE 按叶子/全局决定），每行 IN 判定从 O(k) 降为 O(1)。
- 剪枝同步：`PruningEvaluator.mayMatch(..., globalIgnoreCase)` 对字符串统计边界与谓词值统一折叠；IN 剪枝改为 IN 值区间与块区间求交，避免大小写误剪。
- 验证：JDK 8 `mvn clean package` 全绿，10 个测试通过。端到端新增 3 条链路：SparkConf ignoreCase 命中 44、option=false 命中 0、`lower()` + option=false 命中 44；原有 64/95/108 不变。
- README 已补充开关说明、IN/LIKE 预编译调优项与 lower/upper 支持范围。

## Redis/Redisson 全局 LIMIT 控制

- 用户要求：用 Redis 做分布式全局 limit，每 1000 条更新一次，控制连接数，Java 客户端必须用 Redisson。
- **重要历史**：此前先后实现过「单分区全局计数」和「并行 + 顶层 GlobalLimit」两版，用户都不满意并要求全部回滚（"算了，不是这个效果"）。本次是用户主动要求重新引入 Redis 方案，不是重复旧设计。
- 依赖：Redisson 3.16.3（本地 m2 已有，Java8 兼容），`spark.version` 恢复为用户环境的 3.3.4，test-scope protobuf-java 3.19.6 保留。
- 新建 `limit` 包：`Counter`（可 mock 的原子计数接口）、`LimitBudget`（每 batch 条 getAndAdd 一次，块按全局 limit 裁剪，refund 本地归还）、`RedissonHolder`（按连接参数缓存 RedissonClient 的 JVM 级单例，限制 poolSize，counter.set(0)+expire）。
- 注意 Redisson 3.16.3 的 `RAtomicLong.expire` 参数是 `Instant` 不是 `Duration`。
- `SeekScanBuilder` 实现 `SupportsPushDownLimit`，仅在配置 `seek.redis.address` 时返回 true 并生成 UUID key + driver 初始化 counter；否则返回 false 留给 Spark 顶层 GlobalLimit（向后兼容）。配置在 driver 解析后写入分区 confMap，executor 不依赖 SparkSession。
- `SeekPartitionReader` 每行 tryAcquire，若无行输出则 refund；额度耗尽立即停扫。
- 验证：JDK8 + Spark3.3.4 `mvn test` 全绿（21 测试）。新增 `LimitBudgetTest`（4）、`PushLimitTest`（2）。本机无 redis-server，未做真实 Redis 端到端，只做内存 Counter 单测。
- 警告：pom XML 注释里不能含 `--`（如 `--jars`），否则解析失败——踩坑两次，务必避免。

## Maven 打包内嵌 Redisson（2026-11-26）

- 用户要求：maven 打包时把 redisson 塞进 jar，其他依赖都不要集成。先问过用户两轮：第一轮选"只 shade 独有依赖"，但验证发现本地 Spark 的 netty-all-4.1.74 是 4KB 坏包(缺 AddressResolverGroup)，"复用 Spark netty"不可靠；第二轮用户改选"全 shade + relocation"。
- 方案：maven-shade-plugin 3.5.0，phase=package，artifactSet includes 只含 redisson + 它的传递依赖(netty/reactor/reactive-streams/rxjava/jboss-marshalling/jodd/bytebuddy/javax.cache/jackson/core+dataformat/snakeyaml)，**排除** slf4j(日志门面共享)、Druid、Spark、Hadoop、ORC、Parquet(provided)。
- relocation：io.netty / reactor / org.reactivestreams / io.reactivex / org.jboss.marshalling / org.jodd / net.bytebuddy / javax.cache / com.fasterxml.jackson / org.yaml 全部重定位到 `org.redisson.shaded.*`，与 Spark 自带库完全隔离。加 ServicesResourceTransformer，createDependencyReducedPom=false。
- 注意：relocation 会把项目自己 ConfUtils 里的 Jackson ObjectMapper 引用也改写成 shaded 包，但 shaded jackson 也在 jar 里，测试验证无碍。
- 产物 jar 16MB(未 relocation 版 11MB)。验证：项目类 64、服务注册完好、redisson 1460 类、重定位 netty 1756 类、未重定位 netty/jackson=0、spark/druid=0。
- **关键验证**：仅用 shaded jar + slf4j-api(完全不放外部 netty)，`Class.forName("org.redisson.Redisson")` + `Config.useSingleServer()` + 加载 `org.redisson.shaded.io.netty.channel.nio.NioEventLoopGroup` 全部成功 → 完全自包含成立。
- 坑：`JAVA_HOME/bin/mvn` 不存在(mvn 是系统级)，要用 `JAVA_HOME=... mvn`。XML 注释不能含 `--`。
- JDK8 + Spark3.3.4 全量测试 21 个全绿。README 3.1 / 5.2 已更新：现在只需提交主 jar + druid jar。
